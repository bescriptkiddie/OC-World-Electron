# Journey Maps

## Day 1 / Day 3 / Day 7 Skeleton

### Day 1
- 用户为什么来：想找一个既能听懂自己，又不只是安慰自己的陪伴体。
- 第一次感到被理解的时刻：OC 先准确接住此刻状态，再追问一个真正关键的问题。
- 第一次愿意继续留下的理由：它没有急着教，也没有急着定义，只是把混乱说清了一点。
- 当天最容易流失的点：一开口就被建议、被分析、被归类。
- 当天回访种子：离开对话时，用户心里会留下一个感觉——它好像真的记住了我的状态。

### Day 3
- 用户为什么回来：记得上次那种被理解后的轻松感，还想看看它会不会继续懂自己。
- 关系如何从新鲜感变成轻依赖：每次回来都能感到上下文连续，不需要重新解释自己。
- 行动建议怎样自然出现：在情绪和处境被说准后，只给一个极小动作，当天就能做，不像任务。
- 成长线索怎样第一次出现：沿着当前对话递出一张小纸条，像邀请理解，不像系统通知。
- 这一天最容易流失的点：每次回来都像被推进任务流程，而不是回到一个懂自己的陪伴位。
- 当天回访种子：用户开始觉得，和它多聊几次，自己会更快看清下一步。

### Day 7
- 用户为什么还愿意回来：已经开始把它当成一个稳定的陪伴位，而不是偶尔聊天的工具。
- 成长如何开始被看见：OC 不是给分数，而是指出一条已经反复出现的真实变化线索，并让用户自己决定要不要展开。
- 什么会让关系继续变深：用户发现自己可以校准它，它也会越用越懂自己。
- 这一天最容易流失的点：成长显露开始像系统评判，而不是关系中的共同理解。
- 当天回访种子：用户第一次明确感到，这不是一次次零散聊天，而是一段在慢慢累积的关系和变化。

## Integrated Retention Loop
1. **Day 1：被理解**
   - 核心任务：让用户确认 OC 不是模板回复。
   - 留存理由：它把混乱说清了一点。
   - 禁区：不要急着建议，不要急着解释用户是谁。

2. **Day 3：被陪着往前走**
   - 核心任务：在关系没被破坏的前提下，长出一个现实中的极小动作。
   - 留存理由：和它聊完，不只是舒服一点，还更容易动起来。
   - 禁区：不要把互动变成待办清单或复盘作业。

3. **Day 7：被共同看见变化**
   - 核心任务：把真实生活里重复出现的线索变成可校准的共同理解。
   - 留存理由：用户开始感到“它越来越懂我，我也越来越看见自己”。
   - 禁区：不要把成长可见做成系统评判。

## Loop Strength Check
- 关系：每一段回访动机都先来自被理解和连续性，而不是功能刺激。
- 行动：动作只在 Day 3 才开始明显出现，且依然维持轻量。
- 成长可见：集中在 Day 7 才真正成形，符合渐进显露逻辑。
- Verdict: 当前这条 Day 1 / Day 3 / Day 7 链路成立，可以作为种子用户留存主路径继续保留。
