current project architecture

前台是 OC 与对话，后台是记忆与成长，边界正在从 Electron 壳收口成跨平台 runtime。

现在这个项目仍然是一个 Electron 桌面应用，但核心业务契约已经被重排为 runtime client + optional capabilities。 这意味着前台体验继续围绕 OC、聊天、记忆和成长展开，桌面专属能力被压回 shell，未来 iOS Web / React Native / Swift 只需要补新的 adapter。

one-line read

这不是“网页 + Electron 包壳”

它现在是一套分层明确的产品系统：Electron 提供桌面壳和桥接，`electron/services/*` 提供领域能力，React renderer 通过 `src/runtime/*` 消费统一契约，browser fallback 作为非壳环境的退化路径。

五层结构：Desktop Shell → Bridge → Domain Services → Runtime Adapters → Renderer Surfaces

按现在仓库里的真实边界来画，不混入未来原生 iOS 工程。

现有主链 可复用到未来 iOS 桌面专属 浏览器退化
desktop-only shell

Shell / Transport

Electron Main

`electron/main.ts`

窗口生命周期、权限、透明浮窗、renderer 加载、Hermes runtime 启动。

Preload Bridge

`electron/preload.ts`

把主进程能力注入成 `window.ocWorld`，是 Electron renderer 唯一直接桥。

IPC Router

`electron/ipc.ts`

注册聊天、记忆、growth、TTS、ASR、Hermes、imageGen、floatingOc 的通道。

shared business backbone

Domain Services 与 Runtime 收口

Domain

`electron/services/*`

聊天编排、记忆仓、growth pipeline、recall、relationship、TTS、ASR、Hermes manager、image generation。

Contract

`src/types/index.ts`

前后端共享的 payload / result / status 类型，是跨平台重用的最小契约面。

Capability Facade

`electron/capabilities/facade.ts`

transport-neutral 能力分组雏形，和 runtime client 的命名边界一致。

Adapter A

`src/runtime/electron-client.ts`

把 `window.ocWorld` 包成 `OcWorldClient`，并把 `tts/asr/imageGen/floatingOc` 暴露成 optional capabilities。

Runtime Core

`src/runtime/client.ts` + `context.tsx` + `use-runtime.ts`

`OcWorldClient` 承担跨平台业务接口；`PlatformCapabilities` 承担平台差异点；React 通过 `RuntimeProvider` 注入当前环境。

  • 业务 client：chat / character / relationship / memory / timeline / growth / recall / hermes / airjelly
  • optional capabilities：tts / asr / imageGen / floatingOc
Adapter B

`src/runtime/browser-client.ts`

无 bridge 时提供 browser fallback：角色草稿、本地历史、growth reveal、profile 回写、基础 demo 对话链。

frontend surfaces

Renderer

Entry

`src/main.tsx`

启动时根据 `window.ocWorld` 选择 `createElectronClient()` 或 `createBrowserClient()`。

App Shell

`src/App.tsx` + `OcWorldApp.tsx`

主界面、路由 surface、floating 状态入口，全部改成读 runtime 而不是摸全局桥。

Interaction

`useChat.ts` + views

聊天、记忆、Create、FloatingOcWindow 都通过 injected runtime / capability 走主链。

当前主数据流

这条链既是今天已经成立的产品主线，也是未来 iOS 客户端要复用的核心骨架。

1用户输入

用户从聊天、创建、浮窗、语音进入 renderer surface。

2runtime 分流

`src/main.tsx` 选择 Electron adapter 或 browser adapter。

3业务请求

React 组件和 `useChat` 只调用 `OcWorldClient`，不直接访问 `window.ocWorld`。

4桌面桥接

Electron 环境下由 preload / IPC 把请求送进 `electron/services/*`。

5记忆与成长

聊天、关系、memory、growth、recall、Hermes 状态在后台写回并返回前台。

6平台差异

语音、图片生成、浮窗等通过 optional capability 暴露，给未来 iOS adapter 留接口。

what is already true now

已经收口完成的点

Renderer 主流程已经通过 `src/runtime/*` 统一入口；browser fallback 不再只是占位，而能正确处理 growth confirm / reject / dismiss；TTS / ASR 已支持从 runtime capability 注入。

what is still desktop-only

仍然不能直接搬去 iOS 的点

`BrowserWindow`、preload 注入、`ipcMain/ipcRenderer`、透明浮窗拖拽、Electron 权限模型都还属于桌面壳。未来 iOS 只能复用业务契约和 renderer 结构，不能复用这些宿主能力。
